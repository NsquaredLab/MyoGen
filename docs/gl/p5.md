### Numerical acceptance

Use identical realized inputs for both executions.

Require exact equality for:

- Fibre and MU identities.
- Generated random parameters and final RNG state.
- Spike bins.
- Shapes and ordering.
- Selection semantics.
- Sampling metadata and units.

For waveforms expressed in mV, use this initial engineering gate per channel:

```text
maximum absolute error
    <= 1e-12 mV + 1e-9 × reference peak absolute amplitude
```

Compare both intermediate unnormalized waveforms and final outputs.

Do not align, renormalize, or rescale results to make them agree.

Following prior project guidance, include whole-waveform overlays and measures of amplitude, timing, energy, and interchannel relationships. Matching a peak or centroid alone is insufficient.

These are numerical acceptance limits, not claims of biological validation. If an optimization fails, retain the reference implementation for that operation; do not loosen thresholds automatically.

### Adaptive-memory tests

Use an injected memory probe for deterministic tests:

| Scenario | Expected behavior |
|---|---|
| High available memory | Admit useful work within reserve and margin |
| Two simultaneous worker requests | Combined reservations remain within allowance |
| Memory drops before dispatch | No new work admitted |
| Memory drops during a batch | Respond at the next safe boundary |
| Memory recovers briefly | Do not oscillate immediately to larger batches |
| Memory remains healthy for five samples | Permit bounded growth |
| Smallest batch cannot fit | Zero jobs admitted; clear error or bounded wait |
| Cache eviction does not reduce RSS immediately | Do not assume physical memory was returned |
| Allocation fails before commit | Retry without duplicate contribution or new RNG draws |
| Persistent pressure exceeds 60 seconds | Stop clearly; retain valid completed cache entries |
| Final output itself cannot fit | Reject before starting that stage |
| Monitoring fails | Stop new admissions and report the failure; do not assume unlimited memory |

Also run controlled integration tests with external memory consumption increasing and decreasing. Use a bounded test process, never deliberate system exhaustion.

Record response latency at safe boundaries. Do not promise immediate reclamation from an operation already executing inside a numerical library.

### Measurements and targets

Measure:

- Startup and compilation.
- Realization and preparation.
- MUAP generation.
- Signal assembly.
- Cache reads and writes.
- Complete pipeline, including unchanged stages.
- Available-memory minimum and parent/worker memory.
- Time spent waiting for memory.

Use at least three timed repetitions and report cold and warm behavior separately.

Acceptance targets:

- At least **50% lower peak SFAP working storage** for representative streamed iEMG.
- At least **50% lower temporary storage** during representative long-recording assembly.
- At least **20% improvement in the targeted stage** for optimizations advertised as speed improvements.
- No more than **10% median runtime regression** on small cases without external memory pressure.
- No admission that knowingly violates the reserve, allocation margin, or explicit buffer ceiling.
- Matching numerical results across adaptive batch and worker changes.

A memory-saving change may ship without a speed improvement if it meets its storage target and remains within the runtime-regression limit.

The former fixed 8 GB acceptance ceiling is removed. Acceptance now concerns adaptive reserve behavior and measured performance on the four-core, 16 GB baseline.
