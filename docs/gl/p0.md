
### Release behavior

Keep the existing public models and existing execution path available. Introduce optimized CPU execution as an explicit option for the first release.

Users choose the scientific model separately from the execution method:

| Model and execution | Intended use |
|---|---|
| Basic model, existing execution | Existing workflows and numerical reference |
| Basic model, optimized execution | The same model with lower memory use and less repeated computation |
| Anatomical model | The new anatomical representation and separately validated forward model |

Optimization must preserve the configured fibre population, physiological parameters, electrodes, conductivities, and sampling resolution. Resource pressure changes scheduling and batch sizes, never the scientific model.

### Priorities

| Priority | Improvement | Benefits |
|---|---|---|
| 1 | Adaptive memory and controlled parallelism | Both modalities; responsive system and predictable allocation |
| 1 | Bounded signal assembly | Both modalities; less temporary storage |
| 1 | Streamed fibre-to-MUAP accumulation | iEMG; avoid retaining every fibre waveform |
| 2 | Reusable conductor preparation | sEMG; avoid repeated matrix construction and solves |
| 2 | Prepared-template caching | Both modalities; faster repeated recordings |
| 3 | Persistent cache and import improvements | Both modalities; restartability and easier use |

GPU improvements, altered neural dynamics, reduced-precision arithmetic, surrogates, and anatomical changes are outside this release.

### Public interface

Add an immutable `ExecutionPolicy`, exported through `myogen.simulator`:

```python
execution = ExecutionPolicy(
    backend="cpu",
    memory_budget_mib=None,
    reserve_fraction=0.20,
    reserve_min_mib=4096,
    max_workers=2,
    cache_dir=None,
)
```

Add keyword-only `execution=None` to:

- `IntramuscularEMG.simulate_muaps`
- `IntramuscularEMG.simulate_intramuscular_emg`
- `SurfaceEMG.simulate_muaps`
- `SurfaceEMG.simulate_surface_emg`

Contract:

- Omitting `execution` retains the existing execution path.
- Supplying a policy enables optimized execution.
- `memory_budget_mib=None` enables adaptive allocation without a fixed numerical-buffer ceiling.
- A positive `memory_budget_mib` adds a ceiling; system-reserve protections still apply.
- The first optimized release supports `backend="cpu"`.
- Contradictory explicit GPU arguments raise an explanatory error.
- Existing `n_jobs` conventions remain valid. The resolved count is further limited by `max_workers` and available memory.
- Existing Neo outputs, units, ordering, and sampling metadata remain compatible.

The numerical-buffer ceiling includes retained arrays, caches, worker buffers, and reserved allocations. It does not claim to cap the interpreter or all native-library memory; system monitoring accounts for their pressure separately.
