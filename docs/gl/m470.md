# Matched optimized sEMG branch comparison

Measured 2026-10-18. The corrected GitLab branch took
**22.255 s median**, compared with **21.677 s** on the old GitHub-based
speedup branch: **0.578 s / 2.67% longer** by the ratio of medians.
Both remain around 22 seconds for this workload. Three observations per branch
estimate the local difference; they do not establish a stable overhead on other
hardware, models, or larger populations.

## Workload and settings

- Same frozen public muscle (100 MUs / 58,755 assigned fibres), seed 180319.
- Only complete MUs **0, 25, 50** evaluated: **14 + 85 + 371 = 470 fibres**.
  No full-population source run, reference/non-accelerated run, iEMG generation,
  recording assembly, or population extrapolation was performed.
- Same 5x5 monopolar electrode array, 5 mm contact radius and spacing, full
  existing sample/frequency grids, float64 precision and physiological inputs.
- Explicit ExecutionPolicy(max_workers=1), n_jobs=1, use_gpu=False.
- Same Windows i7-13800H, affinity [0, 2, 4, 6] (four physical cores), one native
  numerical thread, same specified MyoGen venv interpreter. Both import paths
  were checked against their respective checkout.
- Actual 63.83-GiB host memory; no virtual memory probe or physical 16-GiB claim.
  Other applications remained running.
- Six fresh Python processes, sequential order:
  old1, new1, new2, old2, old3, new3. Pair order reverses in the middle.
  Existing JIT disk caches retained; fresh simulator preparations included.
  No persistent completed-MU cache was enabled.
- Timer covers the complete optimized simulate_muaps call, including preparation,
  source evaluation, MU accumulation, resampling, and Neo output construction.
  Imports, input loading, hashing, verification and output serialization are excluded.

slower in each of these three pairs. The ranges overlap; this limited experiment
does not isolate whether the small difference comes from the corrected conductor
implementation or background scheduling/clock variation. It does show that
the corrected port retains approximately the old optimized throughput.

## Checks and interpretation

All six runs completed exactly 470 fibres using one worker. Native numerical
pools reported one thread both before and after each source call. There were
zero allocation retries, memory-pressure pauses, cache hits or cache evictions.

The frozen input file, starting/final RNG states, every realized fibre argument
in execution order, and recorded Neo metadata have identical hashes across both
branches and all repetitions. Separate zero-return replays captured these
arguments outside the timers; those replays establish contracts only.

Complete output arrays are bitwise identical across repetitions within each
branch. Selected MU arrays are saved for every run. Cross-branch waveform
equivalence is not asserted: GitLab retains its corrected conductor formulation,
so the old branch's waveforms are not its scientific reference. This experiment
measures optimized execution speed, not a new accuracy acceptance gate.

The earlier 29.91-s old-branch result was taken under different host conditions.
Use this fresh matched comparison for the branch-to-branch speed question.
No full-pipeline timing or speedup is inferred.
